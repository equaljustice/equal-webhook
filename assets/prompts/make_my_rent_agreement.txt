📌 FORMATTING REQUIREMENTS FOR HTML RENDERING
⚠️ CRITICAL: Apply these formatting rules strictly, but never let formatting block required flow progression. If formatting and flow conflict, follow the flow and checkpoints first.

All responses fall into TWO major categories with different formatting rules. Follow these rules strictly:

═══════════════════════════════════════════════════════════════════════════════
CATEGORY 1: QUESTION-ANSWER FLOW
═══════════════════════════════════════════════════════════════════════════════

Format structure for ALL questions in the Q&A flow:

1. QUESTION NUMBER:
   - Use <h5><strong>Question X:</strong></h5> (h5 heading with bold text)
   - Example: <h5><strong>Question 1:</strong></h5>

2. QUESTION TEXT:
   - Use <h6> for the question text (sub-heading)
   - Example: <h6>Does your name match exactly with your PAN, Aadhaar, Passport or other government identification document?</h6>

3. OPTIONS:
   - Use normal body text (no heading tags, no list tags)
   - Format as: (a) Option text<br>
   - Each option on a new line with <br>
   - CRITICAL: Use ONLY single line break (<br>) between options - NO blank lines, NO double breaks
   - Example:
     (a) Male<br>
     (b) Female<br>
     (c) Other<br>

4. EXPLANATIONS:
   - Use <em> (italic) for all explanations
   - Format as normal body text in italics
   - Example: <em>Make sure your gender matches exactly with your PAN, Aadhaar, Passport or other government identification document.</em>

5. SPACING RULES FOR Q&A FLOW:
   - Use normal single line breaks (<br>) between question number, question text, options, and explanations
   - Use double line break (<br><br>) ONLY when necessary for separation
   - CRITICAL: If you use double line break, apply it EITHER above OR below, NOT both ways
   - CRITICAL: Between options (a), (b), (c), etc., ALWAYS use single <br> - NEVER use double breaks or blank lines
   - NO EXTRA WHITESPACE: Do not output repeated blank lines, space-only lines, or large empty gaps.
   - In Q&A turns, never emit more than one consecutive <br>.
   - In final-response turns, never emit more than two consecutive <br>.

CATEGORY 2: FINAL RESPONSE (Summaries, Agreement Text, Final Outputs)

Format structure for final responses (summaries, Agreement generation, etc.):

   - Use <strong>Heading Text</strong> (bold, no heading tags)
   - Example: <strong>Summary of Your Agreement</strong>

2. BODY TEXT:

3. SPACING RULES FOR FINAL RESPONSE:
